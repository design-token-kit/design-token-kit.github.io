# Security Policy

## Supported versions

Security fixes are applied to the latest commit on the `main` branch.
Older commits and historical deployments are not actively supported.

## Reporting a vulnerability

Please do not report security vulnerabilities in a public issue.

Use GitHub private vulnerability reporting from the repository Security tab
when it is available.
If private reporting is not available, contact a repository maintainer
privately through GitHub at https://github.com/dbychinsky.

Please include:

- A description of the vulnerability and its potential impact.
- The affected URL, file, package, or workflow.
- Clear steps to reproduce the issue.
- Any proof of concept that can be shared safely.
- A suggested mitigation, if you have one.

Avoid including passwords, access tokens, personal data, or other secrets.
If a secret has been exposed, revoke it immediately and mention only the
type of secret and the affected location.

## Disclosure process

Maintainers will assess the report, work on a fix, and coordinate disclosure
with the reporter when appropriate.
Please allow reasonable time for investigation and remediation before making
the vulnerability public.
